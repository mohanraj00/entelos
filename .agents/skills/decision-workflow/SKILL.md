# Decision workflow

Read the project constitution, AGENTS.md and current status. Select one tracked workflow or defect. Keep the complete source-to-correction path in view while changing the smallest relevant part.

Before editing, identify the author surface, caller surface, exact source/environment/data/build, qualification expectations, approval/applicability boundary and affected receipts. State what is proposed versus implemented or tested. Keep application source authority, interpretation, access policy and learning decisions explicit.

Reuse CEL's public language/tools and Git's content/history/CAS. Keep the primitive wire profile honest. A new profile, parser, service, schema abstraction or storage adapter needs a concrete integration reason and explicit contract; an overlap with existing tools is not by itself a rejection.

Use neutral expected examples with explicit failures. Check stale discovery, missing dependencies and invalid input behavior where relevant. Preserve old source/cases/receipts after correction. Replay retains original inputs/build; restatement selects a named later root while retaining the original input. A preparation acknowledgement is not proof of a live resident worker.

Run the named relevant checks, preserve failed runs and report limits. Use the full standalone runner for runtime/profile/lifecycle changes. Record results with the source commit and update the issue/status/backlog. No unscoped model benchmark or production deployment is implied by this skill.
